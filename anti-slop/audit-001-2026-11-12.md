# Network presentation audit

Mode: after, selected by the owner for this change. Scope: the Network row,
network component names, descriptions and their existing selection controls.
This is not a whole-application accessibility certification or a redesign.

## Findings and dispositions

The owner approved both numbered changes before implementation.

1. **LOW, R-05 / C-3: Network had no independent Index row.** Networking
   components were folded into Consensus or Execution using architecture edges.
   **Resolved:** `component.area` now places them in a dedicated Network row,
   with exactly one view-scoped component in each current snapshot.
2. **LOW, R-16 / C-1: Network names hid the shared category and scope.**
   `Consensus Gossipsub` named only gossip although the component also represents
   Req/Resp; neither existing name contained Network. **Resolved:** Map, Index
   and the details panel use Consensus Network or Execution Network. Protocol
   names remain in the descriptions; no whole-network proof claim was added.

No additional fixes were identified within this scope.

## Direction and reasons

The existing `docs/design.md` direction is a light, source-linked technical
inventory for developers and auditors. The audit reads its unchanged visual
style as ENERGY 1 / RHYTHM 1 / MOTION 1: calm labels, uniform inventory rows,
no new motion. The table or map remains the primary surface.

- Network is a separate row because networking is already a distinct component
  area; readers should not need protocol-specific vocabulary to find it.
- Consensus and execution names stay distinct because the underlying protocols,
  snapshots and applicable claims are not interchangeable.
- Existing colors, type, spacing and selection indicators are retained to keep
  this classification change consistent with the surrounding inventory.
- No assets, marketing content, navigation structure, dependencies or CSS were
  added. Native buttons retain the existing accessible names and focus styles.

## Follow-up verification

`npm run verify` passed 201 unit/component/package cases and 32 browser cases.
The Network journeys in `e2e/network.spec.ts` exercised every view at 1280, 390
and 320 pixels against the packaged Worker, not a mock API.

| Interaction | Observed result |
| --- | --- |
| Select each view tab | Its own Network row and component appeared. |
| Focus a Network cell, then press Enter | Correct component heading, protocol description and claim count opened. |
| Switch Index to Map | Matching network node appeared; the details selection persisted. |
| Switch Map back to Index | The original Network cell remained selected. |
| Open consensus network claim | Existing catalogue tests reached fixed-commit varint theorem links with Related and No replay labels. |
| Open execution network | The neutral 0 claims state remained intact. |

An additional browser pass checked all three views in both modes at 1280 and
320 pixels with no console errors or page-level horizontal overflow. Reviewed
screenshots cover desktop Beacon Index, desktop Execution Map, narrow Lean
Index and narrow Beacon Map. The existing table keeps its internal horizontal
scrolling; the map keeps its zoom controls.
